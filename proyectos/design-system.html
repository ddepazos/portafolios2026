Design System

Para mí un sistema de diseño no es una página llena de botones: es una forma de ordenar decisiones para que una interfaz pueda crecer sin perder coherencia. Esta sección reúne la lógica modular, los componentes, estados, reglas de layout y criterios de interacción que uso como base al diseñar productos digitales.

01 · Pensar en sistema

Diseñar componentes antes que páginas aisladas

El material de Atomic Design que tengo archivado en Drive propone dejar de pensar la web como una colección de páginas estáticas y trabajarla como un sistema dinámico de piezas que se combinan. Esa lógica me sirve para separar elementos simples, agrupaciones y estructuras completas sin repetir decisiones.

Nivel 01Átomos

Color, tipografía, iconos, botones, inputs y unidades básicas.

Nivel 02Moléculas

Combinaciones pequeñas: buscador, campo + acción, etiqueta + estado.

Nivel 03Organismos

Cabeceras, formularios, tarjetas, tablas o módulos completos.

Nivel 04Plantillas

Estructuras que ordenan organismos y definen jerarquía de contenido.

Nivel 05Páginas

La composición final, alimentada por contenido y casos reales.

02 · Componentes

La consistencia aparece en los detalles repetidos

El trabajo en Figma parte por frames, guías y grillas, pero gana valor cuando los elementos repetidos se convierten en componentes. En vez de redibujar cada botón o campo, se define una base y se controlan sus variaciones.

03 · Layout y responsive

La grilla ordena, pero no debe rigidizar

Una estructura sólida parte de grillas, guías y restricciones que mantienen alineación, ritmo y consistencia entre pantallas. En desktop, una retícula de 12 columnas entrega flexibilidad para distribuir contenidos; en móvil, la prioridad pasa a la lectura, las zonas táctiles y la reducción de pasos innecesarios.

Desktop

Mayor densidad, comparación lateral y uso de hover cuando aporta contexto.

Tablet

Reorganización de columnas y componentes sin perder jerarquía.

Mobile

Prioridad en lectura, zonas táctiles y acciones principales al alcance.

04 · Reglas de interacción

El sistema tiene que explicar qué está pasando

Claridad

La función de cada componente debe entenderse sin depender de explicaciones externas.

Consistencia

Elementos equivalentes deben conservar apariencia y comportamiento entre pantallas.

Feedback

Cada acción necesita una respuesta visible: éxito, error, carga o cambio de estado.

Accesibilidad

Contraste, foco, navegación con teclado, etiquetas y estados no pueden quedar como detalles finales.

Una regla que atraviesa todo el sistema

Si un usuario tiene que adivinar qué puede hacer, dónde está o si su acción funcionó, el componente todavía no está resuelto.

Caso aplicado · Evaluación de interfaz

Análisis de Front-End

Evaluación de una interfaz administrativa enfocada en navegación, coherencia visual, comportamiento responsive, accesibilidad, retroalimentación y mantenimiento.

UsabilidadAccesibilidadResponsive
Decisiones que se desprenden del análisis
  • Estructurar menús y secciones para que la navegación sea clara incluso para usuarios no técnicos.
  • Mantener identidad visual consistente entre interfaz principal y administración.
  • Dar feedback visible al guardar, eliminar o completar acciones.
  • Trabajar contraste, etiquetas, foco y navegación por teclado como parte del sistema.
  • Construir módulos que puedan mantenerse y evolucionar sin rehacer toda la interfaz.
Resultado

El análisis funciona como una pauta práctica para revisar si una interfaz es coherente, entendible, accesible y sostenible en el tiempo.

Caso aplicado · Construcción UI

Diseño de interfaz con Figma

Construcción de una interfaz a partir de frames, grillas y componentes reutilizables, priorizando orden visual y consistencia entre pantallas.

FramesGrillasComponentes
Proceso aplicado
  • Definir el frame según el dispositivo y el contexto de uso.
  • Organizar contenido con guías y grillas antes de trabajar el detalle visual.
  • Diseñar varias pantallas manteniendo la misma lógica de jerarquía.
  • Convertir botones y elementos repetidos en componentes reutilizables.
  • Comprobar que los cambios globales no rompan la coherencia del sistema.
Resultado

La interfaz deja de depender de decisiones aisladas y pasa a trabajar con reglas que pueden repetirse y escalar.

Caso aplicado · Interacción

Diseño de interfaz e interacción

Definición de estados, feedback, affordances, accesibilidad y comportamiento responsive para que los componentes comuniquen claramente qué puede hacer el usuario.

EstadosFeedbackResponsive
Reglas de interacción
  • Definir estados default, hover, focus, active y disabled para componentes interactivos.
  • Usar feedback inmediato para confirmar acciones y mostrar el estado del sistema.
  • Diseñar affordances claras para reducir la carga cognitiva.
  • Trabajar foco y navegación por teclado como parte de la accesibilidad.
  • Adaptar layout y prioridad de contenido según breakpoints y tamaño de pantalla.
Resultado

Los componentes no solo comparten una estética: también mantienen un comportamiento predecible y consistente.
