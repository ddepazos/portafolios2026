Identidad visual · Caso

Jabones Camii

Marca desarrollada por Diego Pazos

Una identidad pensada para funcionar en distintos formatos.

En Jabones Camii desarrollé la identidad visual de la marca a partir de un sello circular y un lettering de carácter artesanal. El proceso incluyó exploración cromática, versiones monocromas, ajustes del logotipo y aplicaciones sobre producto.

El objetivo fue construir una marca flexible: que pudiera conservar reconocimiento al cambiar de fondo, color o soporte, sin depender de una sola versión del logo.

01 · Exploración

Pruebas de color y contraste para definir el carácter del sello.

02 · Adaptación

Versiones monocromas y lineales para distintos soportes y sistemas de impresión.

03 · Aplicación

Pruebas sobre fotografía y producto para comprobar legibilidad en contexto.

04 · Consistencia

Zona de resguardo y variantes para mantener reconocimiento en diferentes usos.

Resultado

Una identidad que no depende de una sola versión.

El desarrollo dejó un pequeño sistema de marca: versiones a color, monocromas, firma, zona de resguardo y uso sobre fotografía. El lettering y la forma circular mantienen el reconocimiento cuando cambian los colores o el soporte.

01 / Problema y objetivo

Una experiencia creativa integrada

Reunir composición generativa, edición por capas, animación y exportación en una interfaz coherente, con espacio útil para el lienzo y controles contextuales.

02 / UX y arquitectura de información

Flujo de trabajo modular

Biblioteca de módulos → lienzo 2D/3D → inspector de propiedades → capas → línea de tiempo → exportación. El usuario puede alternar herramientas sin abandonar su composición.

03 / UI y componentes

Herramientas consistentes

Barra de herramientas, paneles configurables, controles numéricos, deslizadores, selectores de color, capas, presets y controles de reproducción. Diseño pensado para escritorio y navegador.

04 / Identidad y manual de marca

Geometría como lenguaje

Dirección visual de alto contraste: carbón, blanco y naranja técnico; tipografía sans serif, retículas, líneas paramétricas y composiciones generativas. La trama de doble embudo se estudia como símbolo distintivo.

05 / Arquitectura técnica

Web primero

Interfaz React, TypeScript y Vite; estado de edición con Zustand; gráficos vectoriales SVG y escenas Three.js. Integración de exportación de imagen y vídeo; renderizado remoto con Cloudflare y FFmpeg en desarrollo y validación.

06 / Aplicaciones y adaptación

Web, móvil y escritorio

Web: editor principal publicado. Móvil: adaptación responsiva y experiencia táctil como línea de diseño, no una app nativa publicada. Windows: integración de escritorio prevista después de completar la web.

07 / Diseño de interacción

Movimiento y respuesta

Animación por capas, presets, interpolaciones y línea de tiempo. Continuidad espacial «Repetir» incorporada al código; se mantiene una validación funcional progresiva.

08 / Estado y evolución

Producto en desarrollo activo

La versión web está desplegada. Continúan pendientes la edición individual de patrones, múltiples objetos 3D superpuestos, el preset paramétrico de doble embudo y la verificación completa del render remoto.

09 / Roadmap de integraciones

Un núcleo creativo, múltiples entornos

La estrategia mantiene React como núcleo común. Cloudflare publica la web y proporciona servicios remotos; GitHub conserva el código y el historial. Tauri y LAB Bridge reutilizarán las funciones estables, sin duplicar motores.

01 / Web · publicado / por completar

03 / Windows · posterior

LAB Desktop / Tauri

Reutilizar la interfaz React, incorporar acceso local a archivos, empaquetar instalador y probar memoria, rendimiento y uso sin conexión en Windows.

Salida: instalador probado en equipo real.

04 / Illustrator · integración futura

LAB 3D Bridge

Script JSX para exportar SVG desde Illustrator, servicio local opcional con Python/FastAPI, conversión a geometría Three.js y salida GLB/GLTF o vídeo. Medir rendimiento antes de adoptar el puente.

Salida: flujo Illustrator → LAB verificado.

Regla de implementación: una integración a la vez; verificar compilación, despliegue y funcionamiento antes de avanzar. Sin ramas nuevas ni cambios sobre herramientas estables.
